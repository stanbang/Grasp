# GRASP vision

GRASP is a local-first whiteboard where someone can work through a software idea with their coding agent. The user can see what the agent understood, settle open questions, try a proposed experience and approve a concrete specification before implementation begins.

The workflow is **Describe → Clarify → Retrieve context when useful → Visualize → Prototype → Refine → Approve → Implement**. The board shows what people and agents explicitly share. This includes requirements, assumptions, source evidence, technical decisions, diagrams, prototypes and acceptance criteria. Users can amend any proposal and inspect the sources behind factual claims. The board carries the approved decision forward to the agent that will implement it.

The agent works through an open local MCP interface. GRASP owns the board, feedback, revisions and approval record. The external agent owns the conversation and the code it generates. The same board can be opened by a human in a browser or read by an authorized agent. User approval produces a durable specification that can travel to another tool.

The approved Direction A+ whiteboard is the visual foundation. Technical illustrations, editorial headings, handwritten notes and meaningful connectors give the board room for diagrams, scenarios and unresolved ideas. The Knowledge and Engineering canvases carry forward the study workflow, exact citations and the original RAG walkthrough. Existing graph concepts and source passages retain their identities.

The first proof is a sample project demonstrating the end-to-end workflow. A user describes an AI video editor, resolves publishing and caption requirements, reviews a working browser prototype, leaves visual feedback and approves an updated specification. The implementation engine is general enough to repeat that workflow for a different application.
