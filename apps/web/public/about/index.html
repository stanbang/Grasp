What the benchmark measures

Hit@3 means the required passage appeared within the first three chunks. MRR@3 rewards earlier matches. Scope checks count chunks outside the selected document. Context characters are a rough prompt-size proxy.

What I’d measure next

Use held-out lecture weeks and noisy scans. Grade answer correctness, claim support, citation coverage and abstention separately. Track retrieval and generation p50/p95, input/output tokens, retries and cost per supported answer.

Why use RAG for study notes?

A plain LLM is useful for general explanations. Pasting a passage may also be quicker for a one-off question. Grasp helps when students return to several files, need a specific lecture’s wording, or want to check a quote and page before trusting an answer.

Cost, speed and quality

Index the corpus on import and retrieve a small set per question. Persistent Chroma searches by similarity and SQLite resolves the canonical text and offsets. A wider pool or stronger reranker may help difficult questions and adds processing. Mock mode supports development without provider calls. Live mode sends text to the configured provider during indexing and Q&A.

What I’d change if the baseline fails

Try BM25 or reciprocal rank fusion for exact course terms that semantic retrieval misses. Try a cross-encoder when good candidates rank too low. Try a bounded query rewrite for ambiguous follow-ups. Agentic tools add steps and failure modes. Fine-tuning can help output behavior, while new lecture content belongs in the index. Compare changes on held-out cases before promoting them.

What makes the system production-minded?

The application checks citations against retrieved evidence, places limits on requests and has an optional owner token. Exact quote checks cannot judge every generated claim. Multi-user deployments also need document-level authorization, data isolation and redacted monitoring.
