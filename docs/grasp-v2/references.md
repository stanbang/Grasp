## PayNow reference

- GitHub's connector confirmed the public `Enso-Team/paynow-redesign-demo` repository and read its README, contracts, service documentation, web scripts and browser tests. The contract defines supported journeys, error shapes, service boundaries, a form bridge and timing profiles. The React form bundle is used by the web shell and SwiftUI host. The public deployment uses an in-browser demo backend. The services-backed route is a separate run mode with six Spring Boot services. [README](https://github.com/Enso-Team/paynow-redesign-demo/blob/main/README.md) · [Contracts](https://github.com/Enso-Team/paynow-redesign-demo/blob/main/CONTRACTS.md) · [Services](https://github.com/Enso-Team/paynow-redesign-demo/tree/main/services)
- `pnpm build:demo` and `pnpm e2e:demo` target the static experience. The test reads a real browser state, captures named checkpoints, checks the demo notice and tracks cross-origin or network API traffic in demo mode. The services provide scripted E2E checks and seeded success, timeout, missing-recipient and rejection cases. Phase 0 inspected these checks and exercised E6 on the published demo. It did not execute the reference's local suite or service stack. [Web scripts](https://github.com/Enso-Team/paynow-redesign-demo/blob/main/web/app/package.json) · [Browser E2E](https://github.com/Enso-Team/paynow-redesign-demo/blob/main/web/app/scripts/e2e.mjs) · [Service runs](https://github.com/Enso-Team/paynow-redesign-demo/blob/main/services/README.md)
- Apply the same discipline to GRASP's mode contracts, scoped demo data, failure cases and browser verification. Opening the Engineering Canvas should be local, with each live/mock/recorded route explicit. Assert the expected citable result and network boundary for each. Keep FastAPI/SQLite/Chroma and use actual recorded timing only when it exists.

## Canvas library decision

| Candidate | Fit | Work and constraints |
| --- | --- | --- |
| **React Flow** | Custom React cards and labeled edges, node resizing, grouping, viewport conversion and fit methods, keyboard and screen-reader affordances. Its controlled model fits a mapping from graph IDs to board objects. MIT core. | GRASP owns history, persisted schema, presentation sequence, accessible custom cards and later annotation tools. Use targeted selectors and measure large boards. [API](https://reactflow.dev/api-reference/types/react-flow-instance) · [Subflows](https://reactflow.dev/learn/layouting/sub-flows) · [Accessibility](https://reactflow.dev/learn/advanced-use/accessibility) · [MIT license](https://github.com/xyflow/xyflow/blob/main/LICENSE) |
| **tldraw** | Stronger ready-made drawing, shapes, undo, camera and persistence primitives. | Custom evidence cards and canonical graph mapping are still work. The SDK is source available and requires an appropriate production license/key. A hobby license is discretionary and carries a watermark. [SDK](https://tldraw.dev/) · [License](https://tldraw.dev/community/license) |
| **Excalidraw** | MIT whiteboard with drawing, arrows, text, history and open scene formats. | Its drawing-element and scene model places evidence-rich interactive React cards, structured graph bindings and guided focus on the integration side. Controlled follow-up prototype required before considering it an editor fallback. [Repository](https://github.com/excalidraw/excalidraw) · [Documentation](https://docs.excalidraw.com/) |

Recommend `@xyflow/react`, explicitly named in the Phase 0 brief. The current evidence puts typed cards, source panels and predictable navigation ahead of advanced drawing for the first vertical slice. Use one canvas dependency, verify React 18, keyboard and viewport behavior in the phase gate, and add a small in-board annotation layer later. Consider ELK.js only after a measured layout problem.
